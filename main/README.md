# 迷宫多人疏散实验

Python 3.9 或更新版本。主机提供二维地图，手机通过浏览器进入第一人称 3D 视图。

本项目可按“一场次 = 一个实验试次（trial）”的方式运行，自动收集可发表级别的
逐帧轨迹与汇总数据，并支持参与者身份、知情同意、实验条件/分组标注。

## 启动

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

主机使用终端打印的 `127.0.0.1` 地址。手机与电脑连接同一个 Wi-Fi，扫描主机二维码。
Three.js 0.160.0 已保存在 `static/vendor/`，使用时无需连接外网；许可见 `THREE-LICENSE.txt`。
macOS 优先使用 en0/en1 的地址。如果电脑有多个网卡，可手动指定手机可达的地址：

```sh
MAZE_LAN_IP=192.168.1.20 python main.py
```

运行中的 Python 终端按 Ctrl+C 停止，当前实验汇总保存到 `data/evac_latest.json`，轨迹保存到 `data/evac_latest_tracks.csv`。
每场自然结束、重置人群、重建地图、加载场景或手动归档时，都会另存带时间戳的独立汇总 JSON 和轨迹 CSV，
文件名形如 `evac_<时间戳>_t<场次号>_<运行号>.json`，同一秒内多次落盘也不会互相覆盖。

## 参与者与知情同意

- 默认要求真实参与者填写参与者编号并勾选知情同意才能加入（`MAZE_REQUIRE_CONSENT=1`）。
  手机端会弹出同意层：填写编号、勾选同意后才允许连接；拒绝同意会被服务端以 4005 关闭，
  缺少编号以 4004 关闭。编号与同意状态会写入轨迹与汇总，匿名场景可自行填写内部编号。
- 同一个参与者编号在同一场次内只对应一个身份：换个页面/设备用同一编号重连会复用原身份与既有数据，
  旧连接会被关闭，避免重复计数。
- 纯演示或无需身份校验时可用 `MAZE_REQUIRE_CONSENT=0` 启动，恢复“扫码即可加入”。
- 未采集同意时字段为 `null`（未知），与“明确拒绝”是两种不同状态，分析时需区分。

```sh
MAZE_REQUIRE_CONSENT=0 python main.py   # 演示模式：不做身份/同意校验
```

## 实验元数据与分组

主机“实验信息”面板可填写实验编号、实验条件、分组、主试与备注，并“保存实验信息”“立即归档本场”。
这些字段会写入每场汇总的 `experiment` 块，用于跨场次分组统计。对应接口：

- `GET  /api/experiment`：查看当前实验元数据。
- `POST /api/experiment`：设置元数据（`experiment_id`、`session_id`、`condition`、`group`、`notes`、`operator`，值须为字符串/数字）。
- `POST /api/experiment/archive`：立即把当前场次落盘为独立文件，不影响正在运行的仿真，
  可在一场进行中定期存档以免数据丢失。
- `POST /api/evac/spawn_zone?x0=&y0=&x1=&y1=`：设置人群起始区（格坐标）；不带参数表示恢复全图随机。

## 实验控制

- 主机“NPC 人数”支持 0–300 人，默认 80，真人玩家独立计数、不替换 NPC。
  点击“应用人数并重置人群”后进入待命，计时与轨迹重新开始；保留地图、火源、倍速和在线真人。
  改人数前请先归档需要保留的轨迹。普通重置、重建地图和下一场沿用该人数；重启服务默认 80。
  真人掉线后保留身份与本场结果，重连可继续；重置时清理已离线真人，不会转成额外 NPC，
  且清理前会自动归档当前场次，离线真人的记录不会静默丢失。
- 主机“仿真倍速”可选 0.25×、0.5×、1×、1.5×、2×、3×、4×，运行时立即生效，手机同步显示。
  人物运动、反应时间、火烟、伤害和实验计时一起变速；轨迹和 180 秒限制使用仿真时间。
  暂停与结束不推进时间；重置保留所选倍速，重启服务默认 1×。汇总记录倍速及本场切换历史（仿真秒、倍速）。
  **真人反应时间等人类行为指标使用独立的真实时间轴 `real_t`（墙钟秒），不受倍速影响**，
  保证不同倍速条件下反应时间仍可横向比较。
- NPC 自动寻找出口，且不会走进新的火格；被火封路时停在未着火通道。真人玩家仅在按住前进或后退时主动移动，不操作时减速，仍保留推挤、墙壁和火源斥力，可以自行走进火场。
- 迷宫重建会分配随机种子，也可手动指定；相同种子生成同一张图。主机可导出/加载场景 JSON（地图、出口、火源、人数、风、倍速）。
- 人员倒下时记录时刻和原因（火格 / 烟气）。主机点击人或名单可查看血量、烟剂量和死因。手机端显示血量、烟气和受伤提示。
- 环境边界支持设置水平风速 X/Y（m/s，合速度不超过 8 m/s），默认无风；烟气采用二维平流近似，数据汇总会记录模型假设。
- 主机“人群起始区”可把生成范围限制为格坐标矩形 `(x0,y0)-(x1,y1)`，或“恢复全图”。
  限制起始区可让不同条件下的“初始到出口距离”分布可比，避免起点成为逃生时间的混淆变量；
  设置后需重置人群才对在场个体生效。每个个体都会记录 `initial_exit_distance`（到最近出口的网格距离）
  与 `initial_fire_distance_m`（到最近火源米数），并汇总为 `spawn` 块（含均值/中位数/四分位）。
  真人入场会优先落在离出口较远处，避免“开局即逃生”的无效样本。
- 主机可选择 1–4 个出口及布局（自动分散、四角、四侧）。多出口使用同一个多源距离场，NPC 选择最近可达出口，任一出口到达都会计入逃出；手机端同步显示所有出口。
- 暂停与结束时计时、位置、生命值均冻结；运行中重复点击开始不会清零。
- 结束后点击开始会重置人群开始新一场，并保留火源。
- “重置人群”保留火源；“重置并灭火”清除火源。若出口所在格被火覆盖，重建/清火时会记录 `removed_on_exit` 事件，不再静默丢弃。
- 同一个玩家在另一页面连接后，旧页面停止重连，避免争抢控制。
- 暂停后继续使用有效仿真时长，暂停时间不计入 180 秒实验限制。

## 数据字典

汇总 JSON 关键字段：

- `experiment`：实验编号、场次、条件、分组、主试、备注、ISO8601 起始时间 `t0_iso`。
- `timebase`：`sim_seconds_per_real_second`（本场倍速）、仿真时长与真实时长。
- `real_t_first/last/median`：真实时间轴统计，单位秒。
- `escape_rate_human`、`escape_rate_npc`：分别按真人/NPC 计算的逃生率；`human_online_count` 记录在场真人分母。
- 每个个体：`real_reaction_time`、`real_escape_time`、`real_fail_time`、`delay`（真人固定 0，非延迟驱动），
  以及 `participant_id`、`consent`。
- `fire` 块：`burning_cells`、`events`（含时刻、格坐标、`manual`/`spread`/`removed_on_exit` 来源）、`manual_ignitions`。
- `spawn` 块：起始区与初始到出口/火源距离的分布统计（n/min/max/mean/median/p25/p75）。

轨迹 CSV（`evac_*_tracks.csv`）逐行语义要点：

- `t` 为仿真秒，`real_t` 为真实秒，两列分离记录。
- `state` 为该帧状态：`active` / `escaped` / `failed`；**逐帧变化**，避免把最终结局回填到早期帧。
- `escaped_total`、`failed_total` 为整场常量列（最终结局），与逐帧 `state` 分离，便于区分“此刻是否已逃出”与“整场是否逃出”。
- `fire_distance_m` 为当帧到火源的瞬时距离；`min_fire_distance_m` 为该个体历史最小距离，单调不增。
- `initial_exit_distance`、`initial_fire_distance` 为该个体生成时的起始距离（常量列），用于核查各条件起点是否均衡。
- `participant_id`、`consent` 仅对真人有效。
- 文本字段做 CSV 转义，并对 `= + - @` 开头的值加前缀以防公式注入。

```sh
python -m unittest discover -s tests -v
```

慢连接隔离、NPC 避火、死因记录、种子复现、场景加载、实验元数据、真人真实时间轴与参与者同意校验。
